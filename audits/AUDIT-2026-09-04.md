## 2. Blockers — fix before anything else

### B1. Fabricated quotation (VERIFIED — fetched addyosmani.com)
`posts/13-hooks-enforcement/index.md:179` reads:
> Addy Osmani, "Agent Harness Engineering" (2026): hooks, and making failures "structurally impossible."

The phrase **"structurally impossible" appears nowhere in Osmani's article** (nor does
"structurally harder"). His actual formulation is that you change the system so a specific
mistake becomes *structurally harder to repeat*. Line 22 attributes the concept to
`(Osmani, 2026)` and the TL;DR builds on it.
**Fix:** drop the quotation marks and re-word to Osmani's actual claim, or cite the phrase
to whoever did write it. The idea is fine; the quotation is not.

### B2. Wrong author, wrong content (VERIFIED — fetched martinfowler.com)
"Humans and Agents in Software Engineering Loops" is by **Kief Morris, 04 March 2026**,
published as a guest piece in Fowler's *Exploring Gen AI* series. It is cited as Fowler's
in three places, and its content is misdescribed in one:
- `posts/05-agent-failure-modes/index.md:121` — wrong author **and** wrong gloss. The
  article does not catalogue failure modes; it lays out the humans **outside / in / on**
  the loop autonomy spectrum.
- `posts/15-human-in-the-loop/index.md:18` and `:160` — wrong author, gloss is correct.
- `REFERENCES.md:39` and `:107` — wrong author.

### B3. The series' founding line is misattributed (VERIFIED — fetched both sources)
`posts/01-from-context-to-harness/index.md:21` attributes *"if you are not the model, you
are the harness"* to **Anthropic**. It is **Viv (Vivek) Trivedy's**, from LangChain's "The
Anatomy of an Agent Harness" (10 March 2026). Osmani's own article credits him by name:

> "Viv's one-liner does most of the work: 'Agent = Model + Harness. If you're not the
> model, you're the harness.'"

Post 01 §2 additionally credits `Agent = Model + Harness` to `(Osmani, 2026)`. Both belong
to Trivedy; Osmani popularised them. This is the equation the whole series turns on.

### B4. Post 17's companion violates the exactly-once invariant it teaches (VERIFIED — reproducer)
`code/17-parallel-agents/src/parallel_agents/task_board.py`. `claim()` returns the task
name on any non-raising `os.rename` and never confirms the move took. Under real threads,
two agents are each told they own the same task.

Reproducer — 8 threads, 400 tasks, barrier-synchronised, 8 trials:
```
trial 1: claims=411 unique=400 files_in_claimed=400  <-- DOUBLE-CLAIMED
...
RESULT: 8 of 8 trials violated exactly-once
```
The module docstring claims "exactly one rename succeeds"; the README claims the suite
"proves the key invariant"; Post 17 §2 builds the leaderless-swarm argument on it. **All 8
shipped tests pass and none uses threads**, so the suite is structurally incapable of
seeing this — the same failure shape as the shell-injection bug already recorded in
`tools/PROGRESS.md`.

**Fix:** after `os.rename`, `continue` unless `dst.exists() and not src.exists()`; return
only then. Narrow `except (FileNotFoundError, FileExistsError, OSError)` to `except OSError`
(the first two are subclasses). Add a threaded test with `threading.Barrier`. This is also
a genuinely good teaching moment for the post: an atomic primitive plus an untrusted return
value is not an atomic claim.

### B5. Build #1's token budget is unenforceable, and Build #2's sandbox does not sandbox (VERIFIED — reproducers)

**Build #1** — `code/24-minimal-harness/src/minimal_harness/harness.py`. `run()` tests
`resp.is_final()` (line 66) and on a gate rejection `continue`s at line 78, jumping past
the budget check at line 81. Every gate-rejected turn is free.
```
token_budget = 2000, max_iters = 40
stop_reason  = StopReason.MAX_ITERS
tokens_used  = 40000   -> 20x overrun
```
Post 24 §5 states "The overrun is therefore capped at one iteration." Actual overrun: **38
iterations.** Fix: move the budget check above the `is_final()` branch.

**Build #2** — `code/25-harness-plus/src/harness_plus/sandbox.py`. Three defects:
```
cat /worksecrets/passwd   -> ALLOWED   (raw startswith; sibling dir escapes jail '/work')
cat /work-private/keys    -> ALLOWED   (same)
python -c __import__('os').system('id')  -> ALLOWED   (python + pytest are default-allowed)
subprocess_runner passes cwd= ?  False  (jail never enforced at execution)
```
Fix: `Path(token).resolve().is_relative_to(Path(self.jail).resolve())`; pass `cwd=` to
`subprocess.run`; drop `python`/`pytest` from the default allow-list or document loudly
that allow-listing an interpreter allow-lists everything.

*Calibration note:* the reviewer also claimed relative paths escape the jail. They do not —
`cat ../../etc/passwd` is blocked. One sub-claim in five was overstated.

## 3. Does it need more posts? No.

Six new posts were proposed across the analysts. Each was attacked by three independent
adversarial lenses (duplication / scope / substance). **Five were refuted outright.** One

| Proposal | Lenses upheld | Decision |
|---|---|---|
| Failure & Recovery — retries, idempotency, resuming a dead run | substance ✓, scope split, duplication ✗ | **Fold in** (§3.1) |

| The Model as a Harness Parameter — routing, escalation, fallback | substance ✓, scope ✗, duplication ✗ | Reject — CE Posts 04–05 already teach per-role routing and cascade; it names the term the series defines as out of frame |

### 3.1 The one that nearly made it
The keyword gap is real and stark: across 60,832 prose words there are **zero** occurrences
of `backoff`, `jitter`, `rate limit`, `429`, `circuit breaker`, `dead-letter`, or `durable
execution`. Part III is literally titled *Control & Reliability*.

But the duplication lens is decisive: `posts/17-parallel-agents-shared-repo/index.md` §6
already gives a full treatment of at-least-once delivery, leases, crashed-versus-slow
indistinguishability, idempotence, dedupe at the merge gate, and compare-and-set on finish.
Posts 06 §3, 07 §5 and 24 §3 already teach "an environment failure is an observation, not a
crash." A post that is 60% recap of four existing posts is a weak post.

**Decision: no 27th post.** Add the genuinely new ~1,200 words as sections:
- **Post 19 (Loop Engineering)** — a new section: classifying a failed model call (429 /
  529 / timeout) as retry-with-bounded-backoff rather than as a stop condition, with the
  retry budget charged to the same token/wall-clock budget as everything else.
- **Post 17 §6** — harden it alongside the B4 code fix; the bug and the lesson are the same.
- **Post 03 §4** — one sentence: a transient transport error is not exit ②, ③ or ④.

If you want Part III to deliver on its name as a matter of principle, overrule me — the
substance lens upheld the proposal twice and the material is durable. But it is a section,
not a post, on the evidence.
